Observed on the real Android emulator (`emulator-5554`) at the Phase 3 checkpoint, using `https://todijo.com`:

- The Buyer Home hero's remote image did not render; the actual runtime showed its gradient and title.
- The umbrella mark rendered with an emoji-like multicolor appearance rather than the website's brand mark.

These are observations for Phase 5 investigation, not verified root causes. Phase 4 must not change Buyer or Seller presentation solely for visual polish.

## Phase 5 source-level hardening evidence

- Session restoration, expiry, revocation, refresh concurrency and logout/login isolation: `lib/mobile-session.ts`, `mobile/lib/src/core/network/api_client.dart`, `mobile/lib/src/core/auth/secure_session_store.dart`, `mobile/lib/src/features/auth/auth_repository.dart`; focused mobile session and Flutter race tests passed. Temporary refresh network failures retain the session; server-rejected tokens clear only the matching session.
- Seller/Admin role and ownership: all 31 `app/api/mobile/seller/**/route.ts` and `app/api/mobile/admin/**/route.ts` files were checked for their mobile authorization boundary. The shared `requireMobileSeller`, `requireMobileAdmin`, and `requireMobileSellerCj` paths enforce current server-side identity/store/CJ permission; Flutter route guards provide only presentation gating. Relevant mobile, seller, admin and CJ tests passed.
- OAuth/Turnstile/deep links: `AuthController.handleDeepLink` binds OAuth/registration returns to stored attempts, state and nonce; `checkoutReturnLocation` permits navigation only and reads payment state from the buyer order endpoint. Auth, OAuth, registration and checkout-return tests passed. No deep link grants server authority.
- Checkout, Stripe, refunds/payouts, CJ, stock and pricing: the native checkout re-reads/requotes the cart before server checkout; supplier quotes and current store authorization remain server-owned. Focused checkout, pricing, supplier, freight, Stripe, refund, payout and Safety Gate tests passed. No native financial movement or supplier credentials were added.
- Retry/timeout, offline/cache, duplicate-submit and push lifecycle: `ApiClient` has bounded connection/receive timeouts and a single retry after authorized refresh; transient failure does not erase a valid session. Existing Buyer/Seller/Admin busy/error/retry states, push rotation/revoke tests, pagination and performance tests passed. The remaining native push provider credentials are external.
- Sensitive data, performance, accessibility, localization and responsiveness: source scan found no mobile token/secret logging; production dependency audit and secret scan were clean. Buyer image lists and search use bounded pagination, the responsive hero retains reduced-motion/touch pause, Buyer controls expose localized accessibility labels, and the Flutter suite covers 14-locale parity, RTL and 320/360/390/412px Buyer/Seller/Admin layouts. This source/widget evidence does not replace a credentialed Seller/Admin walkthrough, physical Android, or iOS/macOS verification.
